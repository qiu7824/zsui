# Windows 文字内存与稳定性评估

## 结论

默认实现减少了缓存查询的临时分配和排版数组的预留容量，并修复了 UIA
空值替换及 Windows 缓冲绘制的线程生命周期。四类正式应用的私有内存
变化未形成明确收益，Common 未达到下降 10% 且节省 512 KiB 的目标。
不能把这些修改描述为所有应用显著省内存。

只读字体映射共享作为 `windows-font-sharing` 实验特性保留，`window`
和 `full` 均不启用。三窗口静态内存目标达到，
但最终产物的长期稳定性及合成器首帧准入条件尚未建立，因此不进入默认配置。
字形图集、脏区域绘制和 arena 控件树仍是后续实验方向。

## 版本与方法

代码基线为 `91cda3bb9b362c42276b5508eb2f79cf0d8ce991`，实现提交为
`8b494d4`，跨平台验证对应 `cc40b72dd813a7f0c98a4f7bf192c510aad9da3d`。
基线已经包含借用最终绘制缓冲和隐藏时释放缓存的优化，旧收益不重复计入。

在同一 Windows 11 26300、i7-10700KF、16 逻辑处理器和字体环境上，使用
Rust 1.99.0、release、`opt-level=z`、thin LTO、单 codegen unit、strip symbols
和 panic abort。每个场景采用 10 对独立进程并交替先后顺序；每个可见、隐藏、
恢复阶段采样 20 次，分别预热 3、2、2 秒。未主动裁剪工作集。

每个进程的中位数是独立观察值；95% 区间来自 10,000 次配对 bootstrap。
Private Bytes 是主指标；工作集、峰值、隐藏和恢复数据单列于
[机器可读证据](quality/windows-text-memory-evaluation.json)。负差值表示候选更小。
基线恢复五个改动的 Windows 运行时、渲染及 native 源文件，其余测量代码和
features 与候选一致；每份产物均记录源码及二进制哈希。

## 默认配置的正式应用

| 场景 | 基线 MiB | 候选 MiB | 下降比例 | 配对差值 95% CI（KiB，候选减基线） |
| --- | ---: | ---: | ---: | ---: |
| minimal | 5.295 | 5.119 | 3.32% | -196.0 至 4.0 |
| common | 5.590 | 5.562 | 0.49% | -48.0 至 4.0 |
| full | 6.207 | 6.223 | -0.25% | -108.0 至 78.0 |
| viewer | 9.381 | 9.346 | 0.37% | -112.0 至 140.0 |

四个场景的区间均跨越零，不能确认进程级内存下降。可见、隐藏、恢复的
私有内存、工作集和峰值均未超过 `max(3%, 256 KiB)` 回退门槛。
40 对原生窗口截图逐像素相同。

## 单窗口静态文字场景

| 场景 | 基线 MiB | 候选 MiB | 下降比例 | 配对差值 95% CI（KiB，候选减基线） |
| --- | ---: | ---: | ---: | ---: |
| panel | 5.102 | 5.123 | -0.42% | 0.0 至 26.0 |
| large-text | 5.570 | 5.539 | 0.56% | -178.0 至 78.0 |

两个场景的单窗口内存目标均未达到。
该基准包含同一份生命周期测量和分配计数支持代码，不能用它的绝对值替代
上述正式应用的内存。所有测量确认进程创建身份和窗口可见性，恢复截图匹配。

## 实验特性的三窗口场景

| 场景 | 基线 MiB | 候选 MiB | 下降比例 | 配对差值 95% CI（KiB，候选减基线） |
| --- | ---: | ---: | ---: | ---: |
| panel | 10.461 | 6.926 | 33.79% | -3672.0 至 -3504.0 |
| large-text | 11.205 | 7.619 | 32.00% | -3738.0 至 -3592.0 |

共享仅覆盖有明确所有者的只读字体文件映射。每个窗口仍保留自己的
FontSystem、排版、字形和 hinting 缓存；弱索引不延长资源生命。
首个引擎使用本地数据库，单窗口不支付共享索引成本。混合 100%、150%、200%
DPI 的核心测试验证缓存相互隔离、任一共享者退出及旧排版继续绘制。
这不是物理多显示器切换的认证。

## 稳定性与延迟边界

早期候选完成 20 轮预热、100 轮测量、300 次窗口创建和 200 次隐藏恢复，
测量时间超过 30 分钟。基线和候选都未通过私有内存增长门槛：

| 早期产物 | 可见阶段最终增量 | 关闭静置最终增量 |
| --- | ---: | ---: |
| 基线 | 2.129 MiB | 4.207 MiB |
| 共享候选 | 2.465 MiB | 4.562 MiB |

这些是 JSON 中以二进制哈希标识的早期产物，并非最终特性隔离版的长期通过
证明。GDI、USER 和内核句柄数量稳定，关闭后无 ZSUI 窗口，剩余隐藏窗口为
固定的 GDI+ Hook 和 IME 窗口。另一次 50 轮诊断的 Rust 存活分配在每轮关闭后
均为 2,428 字节；这排除了该诊断中 Rust 持有量持续增加，但不足以区分原生
泄漏、系统缓存和堆保留。

本机一次诊断在窗口失焦后只保留 135/200 个输入字符，UIA 重新聚焦后可读取
实际文本；普通激活请求未建立稳定前台条件。失败和预跑样本全部剔除。
随后[独立 Windows CI 桌面](https://github.com/qiu7824/zsui/actions/runs/40438958638)
完成 10 对进程，每进程分别执行 200 次输入、滚动、恢复，验证前台、编辑器
焦点、实际文字、滚动几何与恢复状态。对照结果如下：

| 操作 | 基线 p95 中位数（ms） | 候选 p95 中位数（ms） | 配对差值 95% CI（ms） |
| --- | ---: | ---: | ---: |
| 输入 | 31.531 | 31.550 | -0.016 至 0.211 |
| 滚动 | 31.944 | 31.967 | -0.057 至 0.164 |
| 恢复 | 31.664 | 31.640 | -0.471 至 6.580 |

三类操作均未观察到超过 `max(5%, 1 ms)` 的中位 p95 退化。恢复操作的区间
较宽，不能作为严格的等效性证明。该测量边界包括原生消息、显式重绘和
`DwmFlush`，不是物理键盘到显示器的完整延迟。窗口就绪时间只是可见性
代理，不是合成器首帧时间；CI 与本机内存数据不混作同一硬件场景。

## 正确性与已修复问题

- 完整键借用查询连续 100 次缓存命中零分配；完整文本与样式仍参与相等比较，
  哈希碰撞不会误用排版。字形和行数组使用精确长度存储，保留塑形精度。
- UIA `SetValue("")` 在基线返回成功却不清空文本；候选通过选择后删除完成
  替换，包含重复清空回归测试和真实 Notepad 验证。
- 缓冲绘制以 UI 线程持有成对初始化/反初始化；进行中的绘制持有资源租约，
  保留整帧缓冲及防闪烁路径。
- 本地格式、273 项无默认测试、942 项 full 测试、324 项 Windows Rust text
  测试、299 项 proof 测试、特性矩阵、原生 smoke 和 UIA 检查通过；远端
  Stable API/Rustdoc 检查通过。
- 66 个 release DirectWrite oracle 用例的前后结果完全相同：61 个通过几何
  门槛，62 个字体面及字形身份完全一致；五个既有加权 emoji/混排差异仍保留。

## 跨平台与自适应布局

[完整 CI](https://github.com/qiu7824/zsui/actions/runs/40435872665) 和
[原生目标验证](https://github.com/qiu7824/zsui/actions/runs/40435872398)
覆盖 Win32、AppKit、Linux Direct、GTK 与 Wayland 的适用场景。
G0 修复了 macOS 进程启动身份和真实隐藏确认，以及 GTK 对话框真实 Escape
输入和消失确认；Ubuntu/Wayland 安装使用有签名验证的官方源及有界重试。
[性能矩阵](https://github.com/qiu7824/zsui/actions/runs/40435872293)保留平台各自
的内存指标，Windows 省内存数值不外推到 macOS/Linux。

自适应布局已支持 Row/Column 约束伸缩、按分配宽度文字换行、自然高度与
溢出滚动、Grid 比例轨道、GridView 动态列数、导航收折和 SplitView
inline/overlay 切换。通用任意 Row/Column 断点规则、Row 多行流式换行和
Grid Auto 内容轨道仍未提供，详见[自适应与可调整布局](resizable-layout.md)。

## 后续准入条件

保留独立成立的分配和正确性修改。启用默认字体共享前，必须取得最终产物的
完整长期私有内存及合成器首帧证据，并收窄恢复延迟的不确定性。字形图集、
局部重绘及 arena 应分别证明净收益，再替换相应稳定实现；不能仅凭架构
形式推定更省内存。
